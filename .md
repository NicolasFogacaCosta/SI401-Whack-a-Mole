# SI401 - Whack-a-Mole

Projeto semestral da disciplina de Programação Web I. O sistema consiste em
uma plataforma web do jogo Whack-a-Mole, com autenticação de jogadores,
registro das partidas, histórico individual e ranking global.

## Tecnologias

- HTML, CSS e JavaScript no front-end;
- PHP no back-end;
- MySQL ou MariaDB para armazenamento persistente;
- Sessões nativas do PHP para controle de autenticação;
- PDO para acesso parametrizado ao banco de dados;
- Não são utilizados frameworks PHP.

## Funcionalidades

### Usuários

- Cadastro de novos jogadores;
- Login com nome de usuário e senha;
- Logout e encerramento da sessão;
- Edição dos dados pessoais permitidos;
- Armazenamento seguro das senhas com `password_hash()`;
- Validação das credenciais com `password_verify()`.

### Partidas

Cada partida deve registrar:

- jogador responsável;
- dimensões do tabuleiro;
- modalidade (`Clássica` ou `Explosiva`);
- pontuação final;
- nível alcançado;
- quantidade de toupeiras acertadas;
- data e hora da partida;
- indicação de finalização ou desistência, quando aplicável.

### Histórico

O histórico apresenta somente as partidas do usuário autenticado, ordenadas da
mais recente para a mais antiga.

### Ranking

O ranking apresenta os melhores resultados de todos os jogadores cadastrados.
O critério utilizado será a maior pontuação final, com desempate pela maior
quantidade de toupeiras acertadas e, em seguida, pela data mais recente.

## Controle de acesso

As páginas públicas são:

- página inicial/login;
- página de cadastro.

Todas as demais páginas exigem autenticação. Caso um usuário não autenticado
tente acessá-las, deverá ser redirecionado para a página de login.

Após o login, o identificador do usuário deve ser armazenado na sessão PHP.
O logout deve:

1. limpar os dados da sessão;
2. destruir a sessão;
3. redirecionar o usuário para o login.

O usuário autenticado só poderá consultar ou alterar os próprios dados. O
identificador do usuário deve ser obtido pela sessão, e não por um valor enviado
livremente pelo formulário.

## Modelo do banco de dados

### Tabela `usuarios`

| Campo | Tipo sugerido | Regras |
|---|---|---|
| `id` | `INT` | Chave primária, auto incremento |
| `nome_completo` | `VARCHAR(150)` | Obrigatório |
| `data_nascimento` | `DATE` | Obrigatório, não editável |
| `cpf` | `VARCHAR(14)` | Obrigatório, único e não editável |
| `telefone` | `VARCHAR(20)` | Obrigatório |
| `email` | `VARCHAR(150)` | Obrigatório e único |
| `username` | `VARCHAR(50)` | Obrigatório, único e não editável |
| `senha_hash` | `VARCHAR(255)` | Obrigatório |
| `criado_em` | `DATETIME` | Preenchido automaticamente |

### Tabela `partidas`

| Campo | Tipo sugerido | Regras |
|---|---|---|
| `id` | `INT` | Chave primária, auto incremento |
| `usuario_id` | `INT` | Chave estrangeira para `usuarios.id` |
| `linhas` | `INT` | Dimensão do tabuleiro |
| `colunas` | `INT` | Dimensão do tabuleiro |
| `modalidade` | `VARCHAR(20)` | `classica` ou `explosiva` |
| `pontuacao` | `INT` | Resultado final |
| `nivel` | `INT` | Nível alcançado |
| `toupeiras_acertadas` | `INT` | Total de acertos |
| `finalizada` | `BOOLEAN` | Indica partida concluída ou desistência |
| `jogada_em` | `DATETIME` | Data e hora do registro |

O relacionamento entre as tabelas é:

```text
usuarios (1) -------- (N) partidas
```

## Instalação e configuração

### Pré-requisitos

- PHP instalado;
- MySQL ou MariaDB instalado e em execução;
- extensão PDO para MySQL habilitada;
- servidor web local, como Apache/XAMPP/WampServer, ou o servidor embutido
  do PHP.

### 1. Criar o banco

No MySQL/MariaDB, crie o banco utilizado pelo projeto:

```sql
CREATE DATABASE whack_a_mole
  CHARACTER SET utf8mb4
  COLLATE utf8mb4_unicode_ci;
```

### 2. Configurar a conexão

Preencha em `app/config/database.php` os dados do ambiente local:

```php
$host = '127.0.0.1';
$database = 'whack_a_mole';
$username = 'root';
$password = '';
```

Não versionar senhas reais no repositório. Em ambientes compartilhados, utilize
variáveis de ambiente ou um arquivo de configuração local ignorado pelo Git.

### 3. Criar as tabelas

Execute o script PHP fornecido pelo projeto:

```text
php database/criar-tabelas.php
```

O script deve informar se a criação das tabelas foi concluída ou se ocorreu
algum erro de conexão ou execução.

### 4. Iniciar o servidor

A partir da raiz do projeto, execute:

```text
php -S localhost:8000 -t public
```

Depois, acesse:

```text
http://localhost:8000
```

Se o projeto estiver sendo executado por Apache/XAMPP ou outro servidor, a URL
de acesso deve ser ajustada conforme a configuração local.

## Requisitos de segurança

- Usar consultas preparadas com PDO;
- Nunca salvar senhas em texto puro;
- Validar todos os dados no servidor;
- Escapar valores exibidos em HTML com `htmlspecialchars()`;
- Verificar a sessão antes de carregar qualquer página protegida;
- Usar o usuário da sessão ao salvar e consultar partidas;
- Impedir alteração de CPF, data de nascimento e nome de usuário;
- Impedir acesso de um usuário às partidas de outro;
- Não utilizar frameworks PHP.

## Roteiro de implementação

1. Configurar o banco e a conexão PDO.
2. Criar o script PHP das tabelas.
3. Implementar cadastro e validações.
4. Implementar login, sessão e logout.
5. Proteger todas as páginas internas.
6. Integrar o resultado do jogo ao registro de partidas.
7. Implementar histórico individual.
8. Implementar ranking global.
9. Implementar edição de cadastro.
10. Substituir os dados estáticos das telas por dados do banco.
11. Testar os fluxos de usuário autenticado e não autenticado.
